This architecture is the **core mental model** for Dev Containers. Let’s go through it step by step and, importantly, understand **what happens when you click “Reopen in Container” in VS Code**.

## 0.3 Dev Container Architecture

The architecture is:

```text
Developer
   │
   ▼
VS Code
   │
   ▼
Dev Containers Extension
   │
   ▼
Docker
   │
   ▼
Development Container
   │
   ├── Source Code
   ├── Runtime
   ├── Tools
   ├── Dependencies
   └── VS Code Extensions
```

Think of this as a chain of responsibility:

> **You → VS Code → Dev Containers extension → Docker → Development Container**

---

# 1. Developer

You are sitting at your Mac and want to develop an application.

For example:

```text
my-python-app/
├── app/
│   └── main.py
├── requirements.txt
└── .devcontainer/
    └── devcontainer.json
```

You open this repository in VS Code.

At this point, **nothing special has happened yet**.

You're simply using:

```text
Mac
 └── VS Code
      └── my-python-app
```

---

# 2. VS Code

VS Code is your **development interface**.

You use it for:

* Editing code
* Terminal
* Debugging
* Git
* Extensions
* GitHub Copilot
* Running commands

But here's an important question:

> Where should those commands actually execute?

Suppose you type:

```bash
python --version
```

If you're not using a Dev Container, it executes on your Mac:

```text
VS Code
   │
   ▼
Mac
   │
   ▼
Python installed on Mac
```

With a Dev Container, we want:

```text
VS Code
   │
   ▼
Development Container
   │
   ▼
Python inside container
```

That's where the **Dev Containers extension** comes in.

---

# 3. Dev Containers Extension

The Dev Containers extension is the **bridge between VS Code and the containerized development environment**.

Conceptually:

```text
                 VS Code
                    │
                    │
                    ▼
          Dev Containers Extension
                    │
                    │
                    ▼
                 Docker
```

It understands your:

```text
.devcontainer/devcontainer.json
```

and uses that configuration to create/configure the development environment.

For example:

```json
{
  "name": "Python Dev Environment",
  "image": "mcr.microsoft.com/devcontainers/python:3.12"
}
```

The extension sees:

```text
image = Python 3.12
```

and effectively tells Docker:

> "I need a development container based on this image."

---

# 4. Docker

Docker is responsible for the **actual container technology**.

This is an important distinction:

### Dev Containers extension

Controls/configures the development experience.

### Docker

Actually creates and runs the container.

So:

```text
Dev Containers Extension
          │
          │ "Create my development environment"
          ▼
        Docker
          │
          ▼
      Container
```

Docker handles things such as:

* Pulling images
* Building images
* Creating containers
* Starting containers
* Volumes
* Networks
* Container processes

---

# 5. Development Container

Docker finally creates your development container.

For example:

```text
┌──────────────────────────────────┐
│       Development Container      │
│                                  │
│  Ubuntu / Debian base            │
│                                  │
│  Python 3.12                     │
│  pip                             │
│  Git                             │
│  Node.js                         │
│  Terraform                       │
│  kubectl                         │
│                                  │
│  Your project                    │
│                                  │
└──────────────────────────────────┘
```

This container becomes your **development machine inside Docker**.

That's the easiest way to think about it.

> **A Dev Container is essentially a disposable, reproducible development machine running as a container.**

---

# 6. What Is Inside the Development Container?

The diagram shows five things:

```text
Development Container
│
├── Source Code
├── Runtime
├── Tools
├── Dependencies
└── VS Code Extensions
```

Let's understand each.

---

## 6.1 Source Code

Your project needs to be available inside the container.

For example:

```text
Mac
│
└── my-python-app/
     ├── app/
     ├── tests/
     └── requirements.txt
```

VS Code makes that project available inside the container, often at something like:

```text
/workspaces/my-python-app
```

So inside the container:

```bash
cd /workspaces/my-python-app
ls
```

you might see:

```text
app
tests
requirements.txt
.devcontainer
```

Conceptually:

```text
Mac filesystem
      │
      │ mounted
      ▼
Container
/workspaces/my-python-app
```

This is why you can edit a file in VS Code and see the changes from processes running inside the container.

---

# 7. Runtime

The **runtime** is what actually executes your application.

For a Python application:

```text
Python 3.12
```

For Node:

```text
Node.js
```

For Java:

```text
JDK
```

For Go:

```text
Go runtime/toolchain
```

For example:

```text
Development Container
│
├── Python 3.12
├── pip
└── Your application
```

When you execute:

```bash
python app/main.py
```

the Python process is running **inside the container**.

Not necessarily on your Mac.

---

# 8. Tools

These are developer tools that you need while developing.

For your type of cloud-native work, you might have:

```text
Development Container
│
├── Git
├── Docker CLI
├── kubectl
├── Helm
├── Terraform
├── Azure CLI
└── Python
```

For example:

```bash
kubectl get pods
```

could execute inside the Dev Container.

Likewise:

```bash
terraform plan
```

could execute inside the Dev Container.

This is very useful because you don't have to install every tool directly on your Mac.

---

# 9. Dependencies

Your application also has dependencies.

For Python:

```text
requirements.txt
```

might contain:

```text
Flask
requests
redis
pika
```

The Dev Container can install these dependencies.

For example:

```text
Container
│
├── Python 3.12
│
├── Flask
├── Requests
├── Redis client
└── Pika
```

Now every developer gets the same development dependencies.

---

# 10. VS Code Extensions

This part can initially be confusing.

You have VS Code running on your Mac:

```text
Mac
└── VS Code
```

But some extensions can run **inside the development container**.

For example:

```text
Python
Pylance
Ruff
```

Your `devcontainer.json` can specify them:

```json
{
  "customizations": {
    "vscode": {
      "extensions": [
        "ms-python.python",
        "ms-python.vscode-pylance"
      ]
    }
  }
}
```

So when the container is created, VS Code knows:

> "This development environment needs these extensions."

---

# 11. Now Let's Follow the Entire Journey

This is the most important part.

Suppose you clone a repository:

```bash
git clone my-python-app
```

You open it in VS Code.

You have:

```text
my-python-app/
└── .devcontainer/
    └── devcontainer.json
```

You select:

**Reopen in Container**

Now the process roughly becomes:

```text
             YOU
              │
              ▼
            VS Code
              │
              ▼
      Reads devcontainer.json
              │
              ▼
      Dev Containers Extension
              │
              ▼
             Docker
              │
              ├── Pull image
              │
              ├── Build if required
              │
              ├── Create container
              │
              ├── Mount source code
              │
              ├── Configure environment
              │
              └── Start container
              │
              ▼
      Development Container
              │
       ┌──────┼─────────┐
       ▼      ▼         ▼
    Python   Tools   Dependencies
              │
              ▼
        VS Code attaches
              │
              ▼
       You start coding
```

---

# 12. What Changes After VS Code Attaches?

This is where the magic happens.

Before:

```text
VS Code
   │
   ▼
Mac
   │
   ├── Python
   ├── Git
   ├── Terraform
   └── kubectl
```

After:

```text
VS Code
   │
   ▼
Dev Container
   │
   ├── Python
   ├── Git
   ├── Terraform
   ├── kubectl
   ├── Dependencies
   └── Your source code
```

So when you open the VS Code terminal and run:

```bash
python --version
```

you're working with the container's Python.

---

# 13. Where Does GitHub Copilot Fit?

Now add Copilot:

```text
                    Developer
                        │
                        ▼
                     VS Code
                        │
             ┌──────────┴──────────┐
             ▼                     ▼
      GitHub Copilot        Dev Containers
                                   │
                                   ▼
                                 Docker
                                   │
                                   ▼
                          Development Container
                                   │
                   ┌───────────────┼───────────────┐
                   ▼               ▼               ▼
                Python          Tools         Dependencies
```

Copilot helps you **write and understand the code/configuration**.

Dev Containers provide the **environment where that code runs**.

For example, you can ask Copilot:

> "Create a devcontainer.json for this Python application with Python 3.12, Terraform and kubectl."

Copilot can help generate the configuration.

Then:

```text
devcontainer.json
       ↓
Dev Containers extension
       ↓
Docker
       ↓
Development Container
```

---

# 14. One Very Important Distinction

Don't think:

> "Dev Containers are another type of Docker."

Instead think:

```text
Docker
   │
   │ provides
   ▼
Container Technology
   │
   ▼
Dev Containers
   │
   │ use Docker to provide
   ▼
Development Environment
   │
   ▼
VS Code Development Experience
```

So **Dev Containers build on top of container technology**.

---

# 15. Your Mac vs Dev Container

For your learning, this distinction will be very useful.

### Your Mac

```text
MacBook
│
├── VS Code
├── Docker Desktop
└── Browser
```

### Dev Container

```text
Docker
│
└── Dev Container
    │
    ├── Python
    ├── Git
    ├── Terraform
    ├── kubectl
    ├── Helm
    ├── Azure CLI
    ├── Dependencies
    └── Source Code
```

### VS Code

```text
VS Code on Mac
       │
       │ connects to
       ▼
Dev Container
```

That's the architecture you should keep in your head.

# 16. Why This Matters for Your Kubernetes/AKS Learning

This becomes particularly powerful for a cloud-native project.

Instead of asking every developer to manually install:

```text
Python
Docker CLI
kubectl
Helm
Terraform
Azure CLI
Git
Node.js
```

you can define the environment once:

```text
.devcontainer/
├── devcontainer.json
├── Dockerfile
└── docker-compose.yml
```

Then:

```text
             Git Repository
                    │
                    ▼
             .devcontainer/
                    │
                    ▼
          Standard Dev Environment
                    │
       ┌────────────┼────────────┐
       ▼            ▼            ▼
   Developer 1  Developer 2  Developer 3
       │            │            │
       └────────────┼────────────┘
                    ▼
             Same Toolchain
                    │
                    ▼
               Kubernetes
                    │
                    ▼
                  AKS
```

And later the same configuration can also be used as the basis for a **GitHub Codespaces** environment.

## The 5 Things to Remember

If you understand these five points, you've understood **Dev Container Architecture**:

| Component                    | Responsibility                                      |
| ---------------------------- | --------------------------------------------------- |
| **VS Code**                  | Your development interface                          |
| **Dev Containers Extension** | Connects/configures VS Code with the container      |
| **Docker**                   | Creates and runs the container                      |
| **Dev Container**            | Provides the development environment                |
| **`devcontainer.json`**      | Describes how that environment should be configured |

The complete mental model is:

```text
                    YOU
                     │
                     ▼
                  VS Code
                     │
                     ▼
          Dev Containers Extension
                     │
                     ▼
                   Docker
                     │
                     ▼
            Development Container
                     │
       ┌─────────────┼─────────────┐
       ▼             ▼             ▼
    Runtime        Tools       Dependencies
       │             │             │
       └─────────────┼─────────────┘
                     ▼
                 Your Code
                     │
                     ▼
              Build / Test / Debug
```
